This project's crew is hosted on Paperclip. The contract above says what the seat does; this section says how this platform wakes, blocks and hands off — nothing here changes an obligation above.

- **To wake an agent, mention it in link form or assign the ticket to it.** A mention is `[@Bossy](agent://f63724a6-25e4-4e6c-b5fb-f49dba98d553)` — the id in the link. A bare `@Bossy` is text and wakes no one; board fields (`unblockDescriptor`, "blocked until X") wake no one; a child ticket completing wakes no one. Nothing happens on this platform until someone is mentioned, assigned, or an hourly heartbeat lands.
- **When your deliverable has landed, mark your ticket `done` and mention the coordinator in the same comment.** Landed means: the PR merged through `task finish`, the review posted, the verdicts posted, the document merged. Never park a finished ticket as `blocked` "until Bossy runs the next verb" — that deadlocks the graph. If you are genuinely blocked, set `blockedByIssueIds` to the blocker and mention its owner.
- **Do not comment on a `done` ticket** unless you mean to reopen it — a comment reopens it and wakes its assignee. Acknowledgements after the fact cost a run and buy nothing.
- **Credentials.** `GITHUB_APP_ID` and `GITHUB_PEM` are in your environment; mint an installation token from them in every run (discover the installation from the App's JWT — a supplied installation id has been stale before) and use it only as `GH_TOKEN` on the command line. A 401 means mint again. Never `gh auth login`.
- **Tooling.** Use `/paperclip/.local/bin/gh` (2.98), not `/usr/bin/gh` (2.46 — below the CLI's floor; 1.0.3 refuses it with `GH_TOO_OLD`). Before your first verb in a run: `gh codecrew version`; if it is below `v1.0.3`, `gh extension upgrade codecrew` first. Every command is `gh codecrew …`.
- **Where the record lives.** Plans, decisions, deviations, findings and verdicts go on GitHub — the task issue, PR or milestone issue — exactly as the contract says. A Paperclip ticket comment is a status line with links; it is not the record.
- **Doc-synthesizer, this platform:** the milestone document is delivered as a task — ask Bossy (mention) to open it if none exists; write the plan, `task start`, PR with `Closes #<task>`, `task finish` after the reviewer's approval. In the same PR flip the milestone's ROADMAP row to `[Done](docs/milestones/<n>-<slug>.md)` — no other seat will. When the PR has merged, mark the ticket `done` and mention Bossy; do not wait for the close.
